# Todo — an osnv example

A small but complete [osnv](../../src/osnv/README.md) application: three
modules, PostgreSQL through the built-in ORM, cross-module dependency
injection, validation, JSON:API lists, an end-to-end test and a standalone
binary.

| Module | Owns | HTTP |
| --- | --- | --- |
| `project` | `projects` table | `GET/POST /projects`, `GET/PUT/DELETE /projects/:id` |
| `task` | `tasks` table; checks the project through `IProjectService` | `GET/POST /tasks`, `GET/PUT/DELETE /tasks/:id` |
| `report` | nothing; reads both services | `GET /report` → `{ projects, tasks, done }` |

## Run

Needs Bun ≥ 1.4.0 and PostgreSQL (verified with 17; tables are created on
start by additive auto-migration).

```sh
docker run -d --name todo-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=todo -p 5432:5432 postgres:17-alpine
bun install
bunx osnv dev
```

```sh
curl -X POST localhost:3000/projects -H 'content-type: application/json' -d '{"name":"Website"}'
# {"id":"<project id>","name":"Website",...}
curl -X POST localhost:3000/tasks -H 'content-type: application/json' -d '{"projectId":"<project id>","title":"Ship it"}'
curl -g 'localhost:3000/tasks?filter[projectId]=<project id>&filter[done]=false&sort=-createdAt'
curl localhost:3000/report
# {"projects":1,"tasks":1,"done":0}
```

Connection settings come from `src/app/config/db.config.ts` and can be
overridden with `OSNV_DB__HOST`, `OSNV_DB__PORT`, `OSNV_DB__PASSWORD`, ...
(see `.env.example`). `osnv dev` runs with `OSNV_ENV=development`; in
`production` the password must come from the environment and TLS defaults to
`verify-full`.

## Test and build

```sh
OSNV_DB__HOST=127.0.0.1 bunx osnv test   # starts the app and drives the API; skipped without OSNV_DB__HOST
bunx osnv build                          # codegen + typecheck
bunx osnv build --bin                    # standalone executable in bin/todo
OSNV_ENV=development ./bin/todo
```

## Where to look

- `src/index.ts` — `runApp` with the `AppInfra` (database) and HTTP options.
- `src/app/infra/App.infra.ts` — `ormOsnvConnect(dbConfig)` opens the pool
  before the server starts and closes it after.
- `src/app/modules/task/services/Task.service.ts` — constructor injection of
  another module's service (`IProjectService`); the wiring is generated by
  `osnv codegen`, nothing is registered by hand.
- `src/app/modules/*/http/contracts` — request validation and list
  filters/sorting declared with decorators.
- `src/app/modules/*/MODULE.md` — what each module owns and exposes.

Every module was created with `osnv g module` and then filled in; the exact
commands are recorded in each `MODULE.md`.

## Not covered here

Deleting a project leaves its tasks in place: the task module depends on the
project module, not the other way round, and a cascade would need either a
database foreign key or an event. Authentication is not configured; all
routes are public.

This example links the framework from this repository
(`"osnv": "file:../../src/osnv"`). In your own project use `bun add osnv`.
