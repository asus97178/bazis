# Маршрутизация и привязка параметров

Основы — декораторы маршрутов, шаблоны, источники аргументов — в главе
[Контроллеры](../overview/controllers.md). Здесь — как маршрутизатор
выбирает метод и как именно аргументы получают значения, со всеми
пограничными случаями.

Все примеры проверены на bazis 0.108.0.

## Какой маршрут совпадёт

```ts
@Controller("tasks")
export class TasksController {
  @Get(":id") byId(id: string) { ... }
  @Get("search") search(q: string) { ... }
}
```

`GET /tasks/search` попадёт в `search`, хотя `:id` объявлен раньше:
**обычный сегмент сильнее параметра**, параметр — сильнее `*остатка`.
Порядок методов в классе не важен. Среди параметров с ограничениями
раньше проверяются более строгие: `:n(int)` прежде `:n(number)`, оба —
прежде `:n` без ограничения.

| Запрос | Что происходит |
| --- | --- |
| `/tasks/42/` | Завершающий слэш не мешает: совпадёт `/tasks/:id` |
| `/TASKS/42` | `404`: путь чувствителен к регистру |
| `/tasks/hello%20world` | `id = "hello world"`: сегмент раскодируется |
| `HEAD /tasks/42` | Обрабатывается как `GET`, без тела |
| `PUT /tasks/42` при одном `@Get` | `405` и заголовок `Allow: GET, HEAD` |
| `OPTIONS /tasks/42` | `405`, если не включён [CORS](../overview/middleware.md#cors-и-журнал-запросов) — тогда предварительные запросы обрабатываются сами |

### Один метод — несколько адресов

Декораторы маршрутов можно ставить друг над другом:

```ts
@Get("a")
@Get("b")
twoRoutes(ctx: HttpContext) { return { path: ctx.path }; }   // /tasks/a и /tasks/b
```

`@All("any")` принимает любой HTTP-метод.

### Одинаковые маршруты

Два маршрута, которые отличаются только именами параметров, — один и тот
же маршрут. Приложение не запустится:

```text
Duplicate route: GET /tasks/:taskId is mapped to both TasksController.byId (/tasks/:id) and
TasksController.again. Routes that differ only in parameter names are the same route; change one of the paths.
```

> [!NOTE]
> Текст ошибки с путями — с версии 0.98.1.

## Параметры маршрута

Параметр метода, имя которого совпадает с параметром шаблона, получает
значение из пути. Тип параметра определяет преобразование:

| Шаблон и тип | `/tasks/42` | `/tasks/abc` |
| --- | --- | --- |
| `:n` и `n: string` | `"42"` | `"abc"` |
| `:n` и `n: number` | `42` | **400** `Validation failed`, в `details` — `{"property":"n","code":"type"}` |
| `:n(int)` и `n: number` | `42` | **404** — маршрут просто не совпал |
| `:n(int)` и `n: string` | — | `bazis codegen` останавливается: `route parameter "n" is constrained to (int), so it arrives as a number; declare it as number` |

Разница важна: ограничение в шаблоне (`(int)`, `(uuid)`…) участвует в
выборе маршрута, а тип параметра — только в преобразовании уже выбранного.
Если адрес с буквами вместо числа — это «нет такого ресурса», ставьте
ограничение; если «неверный запрос» — оставьте тип.

Тип параметра должен совпадать с ограничением: `(int)` и `(number)` —
`number`, `(bool)` — `boolean`, `(uuid)` и `(alpha)` — `string`. Иначе
кодогенерация остановится (с версии 0.116.0; раньше `id: string` молча
получал число).

`*path` получает остаток пути целиком: `/tasks/files/a/b.txt` →
`path = "a/b.txt"`.

## Параметры строки запроса

Параметр метода простого типа, которого нет в шаблоне, берётся из строки
запроса:

```ts
@Get("search")
search(q: string, limit = 10, done = false, tag?: string) { ... }
```

| Запрос | Результат |
| --- | --- |
| `/tasks/search?q=bun` | `q = "bun"`, `limit = 10`, `done = false`, `tag = undefined` |
| `/tasks/search?q=bun&limit=5&done=true&tag=x` | `limit = 5`, `done = true`, `tag = "x"` |
| `/tasks/search` | **400** `Validation failed`, в `details` — `{"property":"q","code":"required"}` |

Тип берётся из аннотации или из значения по умолчанию (`limit = 10` —
число). Параметр с `?` или значением по умолчанию необязателен.

| Тип | Что принимается |
| --- | --- |
| `string` | Любая строка |
| `number` | Любое число, в том числе `1.5`; `abc` — 400 |
| `boolean` | `true`, `false`, `1`, `0`; `yes` — 400 |

Целые числа в простом параметре отдельно не проверяются: `limit=1.5` даст
`1.5`. Если нужен целый `limit` в диапазоне, возьмите
[модель строки запроса](../overview/controllers.md#модели-строки-запроса-и-заголовков)
с `@Validator({ integer: true, range: [1, 50] })` или модель списка из главы
[Списки и JSON:API](lists.md).

Ошибки всех параметров собираются в один ответ `400 Validation failed` с
`details` — как ошибки модели тела (с версии 0.102.0).

### Массивы

Повторяющийся параметр — массив:

```ts
@Get()
list(tag: string[] = [], status?: number[]) { ... }
```

| Запрос | Результат |
| --- | --- |
| `?tag=a&tag=b&status=1&status=2` | `tag = ["a", "b"]`, `status = [1, 2]` |
| без параметров | `tag = []` (значение по умолчанию), `status = undefined` |
| `?status=abc` | **400** `Validation failed`: `Field "status" must be of type number, got: string` |

Подходят `string[]`, `number[]`, `boolean[]`, а также `Array<T>` и
`readonly T[]`. Без значения по умолчанию и без `?` отсутствующий массив
становится пустым `[]`. В документации API массив описан как
необязательный параметр типа `array`.

> [!NOTE]
> Массивы в строке запроса — с версии 0.98.1. Раньше codegen
> останавливался с ошибкой, и значения приходилось читать через
> `ctx.url.searchParams.getAll(...)`.

## Тело, заголовки и всё остальное

| Что нужно | Как получить |
| --- | --- |
| JSON-тело | Параметр-класс — [модель запроса](../overview/validation.md) |
| Заголовок | `apiKey: FromHeader<string, "x-api-key">` или `ctx.header("x-api-key")` |
| Несколько параметров строки запроса или заголовков с проверкой | `FromQuery<SearchQuery>`, `FromHeader<Headers>` — [модели](../overview/controllers.md#модели-строки-запроса-и-заголовков) |
| Тело как текст или форма | `await ctx.text()`, `await ctx.formData()` |
| Все параметры маршрута | `ctx.params` |
| Исходный запрос | Параметр типа `Request` |

Явный источник — `FromQuery`, `FromHeader`, `FromBody`, `FromRoute` — задаётся
типом параметра; подробно — в главе
[Контроллеры](../overview/controllers.md#явный-источник-fromquery-fromheader-frombody-fromroute).
Заголовки, которые относятся к инфраструктуре (ключи, трассировка,
авторизация), по-прежнему лучше читать в [middleware](../overview/middleware.md)
или проверке доступа.

## Что codegen не примет

Если источник аргумента нельзя определить, codegen остановится с
`BAZIS_HTTP_BINDING_UNRESOLVED` и укажет метод и причину:

| Сигнатура | Почему |
| --- | --- |
| `find(filter)` — параметр без типа | Неизвестно, откуда брать значение |
| `create(a: CreateA, b: CreateB)` — две модели тела | Тело у запроса одно; модель строки запроса или заголовков помечайте `FromQuery<…>` / `FromHeader<…>` |
| `list(ids: Date[])` — массив не простого типа | Из строки запроса приходят только строки, числа и логические значения |
| `find({ id })` — деструктуризация | Не поддерживается: используйте имя параметра |
