# Приложение

**Одна строка запускает приложение. Один класс его описывает.** Всё
остальное bazis делает сам: проверяет настройки, связывает сервисы,
открывает подключения, поднимает сервер, а при остановке даёт доработать
начатым запросам.

## Точка входа: три строки

```ts
// src/index.ts
import { runApp } from "bazis/core/app";
import { Application } from "./app/App";

await runApp(Application);
```

Этот файл создаёт `bunx bazis new`, и обычно трогать его не придётся.
Чем одно приложение отличается от другого, описано не здесь, а в `App.ts`,
поэтому точка входа у всех проектов одна и та же.

`runApp` запускает приложение и держит процесс, пока его не остановят:
Ctrl+C в терминале или сигнал от Docker и Kubernetes.

## Объявление: один класс

```ts
// src/app/App.ts
import { App } from "bazis/core/app";
import { AppModule } from "./modules/App.module";

@App({
  modules: [AppModule],   // из чего состоит
  http: { health: true }, // HTTP-сервер и маршрут /health
})
export class Application {}
```

Таким этот класс создаёт `bunx bazis new`. Прочитали его — и знаете о
приложении главное: из каких модулей оно состоит и какие серверы поднимает.
Других мест, где приложение «тайно» настраивается, нет.

Понадобилась база данных или Redis — описываете подключения в классе с
`@Infra` и подключаете всю инфраструктуру к приложению одной строкой:

```ts
// src/app/App.ts
import { App } from "bazis/core/app";
import { AppModule } from "./modules/App.module";
import { AppInfra } from "./infra/App.infra";

@App({
  modules: [AppModule],
  infra: AppInfra,        // база данных, Redis и т. п.
  http: { health: true },
})
export class Application {}
```

Как описать подключения — в [«Инфраструктуре»](../infra/overview.md).

Что ещё можно указать в `@App`, как задать порт и адрес, все опции
HTTP-сервера и ядра — в [«Настройках приложения»](settings.md).

## Что происходит при запуске

bazis сначала всё проверяет и только потом открывает порт:

1. **Настройки.** Нет обязательного секрета или значение не того типа —
   приложение не стартует.
2. **Сервисы.** Граф зависимостей проверяется целиком: никто не зависит от
   незарегистрированного сервиса и не берёт чужое в обход `exports`.
3. **Подключения.** Открываются база данных и кэш, запускаются фоновые
   службы, затем HTTP-сервер. Контроллеры bazis находит сам во всех
   модулях — перечислять их не нужно.

Если что-то не так, вы узнаёте об этом сразу, а не от первого пользователя.
Запуск останавливается с кодом 1 и понятной причиной:

```text
[bazis] configuration error: Invalid configuration (environment "production"):
auth.jwtSecret — required non-empty secret is not set (BAZIS_AUTH__JWTSECRET).
```

Когда всё в порядке, в журнале появляется строка с адресом сервера (в
терминале вне production вместо неё — [экран запуска](../cli/commands.md#экран-запуска)):

```text
info: bazis started {"environment":"development","debug":true,"configKeys":2,"configMs":0.2,"containerMs":2,"hostedServices":3,"hooks":0,"startupMs":46,"listening":["http://127.0.0.1:3000"]}
```

## Остановка: начатые запросы дорабатывают

По Ctrl+C или по `SIGTERM` (так останавливают Docker и Kubernetes)
приложение уходит аккуратно:

1. Перестаёт принимать новые соединения.
2. Даёт доработать запросам, которые уже выполняются.
3. Останавливает фоновые службы и закрывает подключения.

Например, запрос выполняется 2 секунды, а `SIGTERM` приходит через
полсекунды после его начала. Клиент всё равно получает `200`, а процесс
завершается с кодом 0.

На остановку отводится 10 секунд (`kernel.shutdownTimeoutMs`). Не
уложились — процесс завершается принудительно. Второй Ctrl+C завершает его
сразу.

### Коды выхода

| Код | Когда |
| --- | --- |
| `0` | Обычная остановка |
| `1` | Ошибка при запуске, необработанная ошибка или остановка не уложилась в срок |
| `130` | Второй сигнал во время остановки |
| Свой | Остановка из кода — см. [Настройки приложения](settings.md#остановить-из-кода) |

### Забытая ошибка не оставит процесс «полуживым»

Если ошибку не поймал никто (например, `Promise` запущен без `await` и без
`.catch`), bazis пишет её в журнал и аккуратно останавливается с кодом 1.
Docker, Kubernetes или systemd перезапустят процесс начисто, вместо того
чтобы он работал в непонятном состоянии.

```text
error: Unhandled error, shutting down {"error":{"name":"Error","message":"forgotten promise",...}}
```

Ошибки внутри обработки запроса сюда не относятся: их превращает в `500`
[обработчик ошибок](../module/controllers/errors.md).

## Приложение без HTTP

Уберите поле `http`, и сервер не поднимется: останутся фоновые службы. Так
пишут обработчики очередей и планировщики.

```ts
@App({ modules: [WorkerModule], infra: AppInfra })
export class Worker {}

await runApp(Worker);
```

Работает до сигнала и останавливается так же аккуратно.
