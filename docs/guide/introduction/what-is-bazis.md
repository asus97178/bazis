# Что такое bazis

**Напишите API на TypeScript. Разверните его одним файлом.**

bazis — бэкенд-фреймворк для [Bun](https://bun.com). В нём уже есть HTTP API,
валидация, OpenAPI и ORM для PostgreSQL. Можно сразу писать первый маршрут, а
готовое приложение собрать вместе с Bun в один исполняемый файл.

[Установить bazis →](installation.md) · [Собрать первый сервис](first-steps.md)

## На сервер едет один файл

Вот как выглядит сборка и доставка приложения `shop` на сервер Linux x64.
Команду можно запустить прямо с Mac:

```sh
bunx bazis build --bin --platform linux-x64
scp bin/shop server:/srv/
```

Внутри `bin/shop` — ваше приложение и Bun. На сервере нужны только этот файл,
настройки окружения и доступ к PostgreSQL. Устанавливать Bun, Node.js и
`node_modules` не нужно. Файл можно запустить как обычную службу или положить
в Docker-образ на Debian или Ubuntu. Откат — это запуск предыдущего файла.

Подробнее — в [«Один исполняемый файл»](../deployment/single-executable.md) и
[«Платформы»](../deployment/platforms.md).

## Ноль сторонних зависимостей

У пакета `bazis` нет ни одной сторонней npm-зависимости. Драйвер PostgreSQL,
клиент Redis, JWT, валидация, OpenAPI, WebSocket, gRPC и CLI — часть
фреймворка или самого Bun. В `node_modules` проекта будут только ваши пакеты
и TypeScript, который нужен для кодогенерации.

Меньше чужого кода — меньше того, что может сломаться при обновлении, и меньше
риска получить уязвимость или вредоносный код через пакет, о котором вы даже
не знали.

## Первый маршрут — без сборки стека по частям

Создайте контроллер, опишите входные данные и подключите PostgreSQL.
Маршрутизация, валидация запросов, авторизация, OpenAPI и миграции уже входят
в bazis: не нужно подбирать и склеивать ORM, валидатор и DI-контейнер из разных
библиотек.

Когда у сервиса появятся новые задачи, в том же фреймворке уже есть фоновые
службы, кэш в памяти или Redis, WebSocket, gRPC, бизнес-процессы и инструменты
для AI-агентов.

## Обычный TypeScript внутри модуля

Если вы работали с NestJS или ASP.NET Core, структура будет знакомой: модули,
контроллеры, сервисы и `DbContext`. Чтобы передать сервис в контроллер,
достаточно указать его тип в конструкторе:

```ts
export class GreetingController {
  constructor(private readonly greetings: GreetingService) {}
}
```

bazis связывает классы по типам при кодогенерации, которую CLI запускает
автоматически. Модуль явно объявляет через `exports`, чем могут пользоваться
соседние модули. А если забыли настроить зависимость или задать обязательный
секрет, сервис сообщит об этом при запуске, до первого запроса.

Соответствие понятий NestJS и bazis — в [«Основных понятиях»](essentials.md#если-вы-знаете-nestjs).

## Попробуйте на небольшом API

bazis подойдёт, если вы выбираете TypeScript и PostgreSQL и хотите упростить
путь от первого маршрута до развёртывания.

Ограничения: фреймворк работает только на Bun, встроенный ORM поддерживает
только PostgreSQL, а в версиях `0.x` минорные обновления могут менять API.
Подробнее о выборе среды — в [«Почему только Bun»](why-bun.md).
