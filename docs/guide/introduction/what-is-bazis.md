# Что такое bazis

bazis — модульный фреймворк для бэкенда на TypeScript, который работает на
[Bun](https://bun.com). Приложение собирается из модулей; каждый модуль
объявляет свои сервисы, контроллеры и данные, а связывает их внедрение
зависимостей (DI).

Если вы писали на NestJS или ASP.NET Core, большая часть понятий будет
знакомой: модули, провайдеры, контроллеры, модели запросов, `DbContext`.

## Что входит в коробку

| Задача | Что есть в bazis |
| --- | --- |
| Структура приложения | Модули `@Module`, DI с временем жизни `scoped` / `singleton` / `transient` |
| HTTP API | Контроллеры, маршрутизация, модели запросов с валидацией, middleware, авторизация, OpenAPI |
| База данных | ORM для PostgreSQL: `DbContext`, типизированные запросы, миграции |
| Конфигурация | Объявления с типами, значения по окружениям, переопределение через `BAZIS_*`, секреты |
| Реальное время | WebSocket с подтверждениями доставки, gRPC-сервер и клиент |
| Фоновая работа | Фоновые службы с управляемым запуском и остановкой |
| Кэш | Кэш ответов и методов, в памяти или в Redis |
| AI | Агенты, инструменты (Tools), подключение LLM |
| Инструменты | CLI: создать проект, сгенерировать модуль, запустить, протестировать, собрать бинарник |

## Чем bazis отличается

**DI без ручной регистрации зависимостей.** Вы пишете обычный конструктор:

```ts
export class GreetingController {
  constructor(private readonly greetings: GreetingService) {}
}
```

Перед запуском кодогенерация читает типы параметров конструктора и записывает
связи в `src/generated`. Декораторов `@Injectable`, `@Inject` и библиотеки
`reflect-metadata` нет: декораторы — стандартные (TC39), Bun выполняет их сам.
Команды `bazis dev`, `bazis test` и `bazis build` запускают кодогенерацию
автоматически.

**Один исполняемый файл.** `bazis build --bin` собирает приложение вместе с
Bun в один файл. На сервер достаточно скопировать его — без `node_modules` и
исходников.

**Ошибки — при старте, а не в середине работы.** Неверная конфигурация,
отсутствующий секрет в `production`, не связанная зависимость или неизвестный
параметр метода контроллера останавливают запуск с понятным сообщением.

**Явные границы модулей.** Модуль сам решает, что отдать наружу через
`exports`. Если `exports` объявлен, остальные сервисы модуля другим модулям
недоступны; CLI создаёт модули сразу с `exports`.

## Соответствие понятиям NestJS

| NestJS | bazis |
| --- | --- |
| `@Module({ providers, controllers, imports, exports })` | `@Module({ providers, controllers, imports, exports })` |
| `@Injectable()` + провайдер | `scoped(Service)` / `singleton(Service)` в `providers`, без декоратора |
| `@Inject(TOKEN)` | Тип параметра конструктора; контракт — абстрактный класс, как и в NestJS, или интерфейс с токеном `createToken<T>()` |
| DTO + `class-validator` | `@RequestModel()` + `@Validator({...})` |
| Guards | `@Authorize(...)` |
| Interceptors / Pipes | Маршрутный middleware и фильтры действий |
| TypeORM / Prisma | Встроенный ORM: `DbContext`, `DbSet` |
| `@nestjs/config` | `defineConfig` |
| Nest CLI | `bazis` CLI |

## Когда bazis подходит

- Нужен бэкенд на TypeScript с понятной модульной структурой.
- Хочется развёртывать один файл без `node_modules` на сервере.
- Данные лежат в PostgreSQL.

## Когда стоит выбрать другое

- Приложение должно работать на Node.js или Deno — bazis работает только на
  Bun, подробнее в [«Почему только Bun»](why-bun.md).
- Нужна другая СУБД: встроенный ORM поддерживает только PostgreSQL.
- Нужна стабильность API на годы вперёд: bazis пока в версиях 0.x, и минорная
  версия может содержать несовместимые изменения (патч-версия — нет).
