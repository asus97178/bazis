# Что такое bazis

**Напишите API на TypeScript. Разверните его одним файлом.**

Ноль сторонних npm-зависимостей. Один исполняемый файл на сервере.

bazis — бэкенд-фреймворк для [Bun](https://bun.com/). В нём уже есть HTTP API, валидация, OpenAPI и ORM для PostgreSQL. Можно сразу писать первый маршрут, а готовое приложение собрать вместе с Bun в один исполняемый файл.

[Установить bazis →](installation.md) · [Собрать первый сервис](first-steps.md)

## На сервер едет один файл

Вот как выглядит сборка и доставка приложения `shop` на сервер Linux x64. Команду можно запустить прямо с Mac:

```sh
bunx bazis build --bin --platform linux-x64
scp bin/shop server:/srv/
```

Внутри `bin/shop` — ваше приложение и Bun. На сервере достаточно исполняемого файла, настроек окружения и доступа к PostgreSQL. Устанавливать Bun, Node.js и `node_modules` не нужно. Файл можно запустить как обычную службу или положить в Docker-образ на glibc, например `debian:bookworm-slim`. Откат — это запуск предыдущего файла.

## Ноль сторонних зависимостей — и первый маршрут сразу

У самого пакета `bazis` ноль сторонних npm-зависимостей: в `node_modules` проекта будут только ваши пакеты и TypeScript. Нечему разъехаться после обновления и некого проверять после очередного отчёта об уязвимости в чужом пакете.

Создайте контроллер, опишите входные данные и подключите PostgreSQL. Маршрутизация, валидация запросов, авторизация, OpenAPI и миграции уже входят в bazis — стек не нужно собирать по частям.

Когда у сервиса появятся новые задачи, в том же фреймворке уже есть фоновые службы, кэш в памяти или Redis, WebSocket, gRPC, бизнес-процессы и инструменты для AI-агентов.

## Обычный TypeScript внутри модуля

Если вы работали с NestJS или ASP.NET Core, структура будет знакомой: модули, контроллеры, сервисы и `DbContext`. Чтобы передать сервис в контроллер, достаточно указать его тип в конструкторе:

```ts
export class GreetingController {
  constructor(private readonly greetings: GreetingService) {}
}
```

bazis связывает классы по типам при кодогенерации, которую CLI запускает автоматически. Модуль явно объявляет через `exports`, чем могут пользоваться соседние модули. А если забыли настроить зависимость или задать обязательный секрет, сервис сообщит об этом при запуске, до первого запроса.

### Если вы приходите с NestJS

| NestJS | bazis |
| --- | --- |
| `@Module({ providers, controllers, imports, exports })` | `@Module({ providers, controllers, imports, exports })` |
| `@Injectable()` + провайдер | `scoped(Service)` / `singleton(Service)` в `providers`, без декоратора |
| `@Inject(TOKEN)` | Тип параметра конструктора; контракт — абстрактный класс или интерфейс с токеном `createToken<T>()` |
| DTO + `class-validator` | Класс с `@Validator({...})`; `@RequestModel()` — по желанию |
| Guards | `@Authorize(...)` |
| Interceptors / Pipes | Маршрутный middleware и фильтры действий |
| TypeORM / Prisma | Встроенный ORM: `DbContext`, `DbSet` |
| `@nestjs/config` | `defineConfig` |
| Nest CLI | `bazis` CLI |

## Попробуйте на небольшом API

bazis подойдёт, если вы выбираете TypeScript и PostgreSQL и хотите упростить путь от первого маршрута до развёртывания. Фреймворк работает только на Bun, встроенный ORM поддерживает PostgreSQL, а в версиях `0.x` минорные обновления могут менять API. Подробнее о выборе среды — в статье [«Почему только Bun»](why-bun.md).
