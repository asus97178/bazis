# Что такое bazis

bazis — фреймворк для бэкенда на TypeScript, в котором всё нужное серверу уже
есть внутри, а на сервер уезжает один файл.

HTTP API, база данных, авторизация, фоновые службы, WebSocket, gRPC,
бизнес-процессы и AI-агенты — часть фреймворка, а не набор пакетов, которые
надо подобрать, связать и обновлять. Работает на [Bun](https://bun.com),
поэтому стартует быстро и выполняет TypeScript без сборки.

```sh
bunx bazis new shop
cd shop && bun install
bunx bazis dev                     # приложение на http://127.0.0.1:3000
bunx bazis build --bin             # bin/shop — готово к выкладке
```

## Почему bazis

### Ноль сторонних зависимостей

У пакета `bazis` нет ни одной runtime-зависимости. Единственная
peer-зависимость — TypeScript, и он нужен только для кодогенерации при
разработке.

Всё остальное фреймворк делает сам или берёт из Bun:

| Задача | Обычно ставят | В bazis |
| --- | --- | --- |
| PostgreSQL | `pg`, Prisma, TypeORM | свой ORM поверх `Bun.SQL` |
| Redis | `ioredis` | встроенный клиент Bun |
| Валидация | `class-validator`, `zod` | свой `@Validator` |
| DI | `reflect-metadata`, `inversify` | DI на кодогенерации |
| JWT | `jsonwebtoken`, `jose` | свой `library/jwt` с ротацией ключей |
| OpenAPI | `swagger-*` | генерируется из контроллеров |
| gRPC | `@grpc/grpc-js` | свой сервер и клиент |
| Тесты | Jest, Vitest | `bun:test` |

Что это даёт:

- **Безопасность цепочки поставок.** В `node_modules` нет сотен пакетов
  неизвестных авторов, поэтому меньше мест, куда может попасть вредоносный код.
- **Обновления без сюрпризов.** Обновляется один пакет, а не дерево из
  транзитивных зависимостей с их несовместимостями.
- **Быстрая установка.** `bun install` скачивает bazis и TypeScript, и всё.
- **Сборка без интернета.** `bazis new --vendor` кладёт фреймворк в проект,
  и такой проект собирается в закрытом контуре без доступа к npm.

### Один исполняемый файл

`bazis build --bin` собирает приложение вместе с рантаймом в один файл:

```text
  [OK  ]  compile         bin/shop · 62.6 MB                              198 ms
```

На сервере не нужны ни Bun, ни Node.js, ни `node_modules`, ни исходники.
Скопировали файл и запустили. Docker не обязателен, хотя с ним всё тоже
работает. Можно собрать файл для другой платформы (`--platform linux-x64`)
прямо с ноутбука. Подробнее в [«Один исполняемый файл»](../deployment/single-executable.md).

Следствия для эксплуатации:

- выкладка — это копирование одного файла, откат — возврат прошлого;
- исходный код не попадает на сервер;
- в окружении нечего «доустановить», поэтому нет расхождений между серверами.

### DI без шаблонного кода

Вы пишете обычный конструктор, а связи между классами находит кодогенерация:

```ts
export class GreetingController {
  constructor(private readonly greetings: GreetingService) {}
}
```

Нет `@Injectable`, `@Inject` и `reflect-metadata`. Декораторы — стандартные
(TC39), Bun выполняет их сам. `bazis dev`, `bazis test` и `bazis build`
запускают кодогенерацию автоматически.

### Ошибки при старте, а не у пользователя

Неверная конфигурация, отсутствующий секрет в `production`, не связанная
зависимость или неизвестный параметр метода контроллера останавливают запуск
с понятным сообщением. Приложение, которое запустилось, собрано правильно.

### Модули с явными границами

Приложение собирается из модулей. Модуль сам решает, что отдать наружу через
`exports`, и остальные его сервисы другим модулям недоступны. CLI создаёт
модули сразу по этим правилам (`bazis g module`), поэтому структура проекта
не расползается по мере роста.

## Что входит в коробку

| Задача | Что есть в bazis |
| --- | --- |
| Структура приложения | Модули `@Module`, DI с временем жизни `scoped` / `singleton` / `transient` |
| HTTP API | Контроллеры, маршрутизация, модели запросов с валидацией, middleware, авторизация, OpenAPI |
| База данных | ORM для PostgreSQL: `DbContext`, типизированные запросы, миграции, динамические модели |
| Безопасность | JWT с ротацией ключей, права модулей, CORS и заголовки безопасности, секреты |
| Конфигурация | Объявления с типами, значения по окружениям, переопределение через `BAZIS_*` |
| Реальное время | WebSocket с подтверждениями доставки, gRPC-сервер и клиент |
| Фоновая работа | Фоновые службы с управляемым запуском и остановкой |
| Бизнес-процессы | Процессы с версиями, задачи сотрудникам, таймеры, повторы и расписание |
| Кэш | Кэш ответов и методов, в памяти или в Redis |
| AI | Агенты, инструменты (Tools), подключение LLM |
| Инструменты | CLI: создать проект, сгенерировать модуль, запустить, протестировать, собрать бинарник |

## Если вы знаете NestJS

Большая часть понятий будет знакомой: модули, провайдеры, контроллеры, модели
запросов. Разница в том, что bazis не требует отдельных пакетов для каждой
задачи и обходится без декораторов DI.

| NestJS | bazis |
| --- | --- |
| `@Module({ providers, controllers, imports, exports })` | `@Module({ providers, controllers, imports, exports })` |
| `@Injectable()` + провайдер | `scoped(Service)` / `singleton(Service)` в `providers`, без декоратора |
| `@Inject(TOKEN)` | Тип параметра конструктора; контракт — абстрактный класс, как и в NestJS, или интерфейс с токеном `createToken<T>()` |
| DTO + `class-validator` | Класс с `@Validator({...})`; `@RequestModel()` — по желанию |
| Guards | `@Authorize(...)` |
| Interceptors / Pipes | Маршрутный middleware и фильтры действий |
| TypeORM / Prisma | Встроенный ORM: `DbContext`, `DbSet` |
| `@nestjs/config` | `defineConfig` |
| Nest CLI | `bazis` CLI |

## Честно об ограничениях

- **Только Bun.** Node.js и Deno не поддерживаются. Это осознанный выбор, и
  именно он позволяет обойтись без зависимостей, подробнее в
  [«Почему только Bun»](why-bun.md). На сервере Bun не нужен, если
  выкладывать бинарник.
- **Только PostgreSQL** во встроенном ORM.
- **Версии 0.x.** Минорная версия может содержать несовместимые изменения,
  патч-версия — нет.
