# Плавная остановка и health

Как приложение останавливается по сигналу, сколько ждёт и что видит
оркестратор через `/health`. Порядок остановки служб и хуки — в главе
[Жизненный цикл](../fundamentals/lifecycle.md#порядок-запуска-и-остановки),
сами проверки — в главе [Health checks](../fundamentals/health-checks.md).

Все примеры проверены на bazis 0.111.2: исполняемый файл, запущенный
как в production.

## Что происходит по `SIGTERM`

`SIGTERM` и `SIGINT` (`Ctrl+C`) запускают плавную остановку:

1. HTTP-сервер перестаёт принимать новые соединения.
2. Запросы, которые уже выполняются, доделываются.
3. Останавливаются фоновые службы, затем закрываются подключения к базе и
   другой инфраструктуре.
4. Процесс выходит с кодом 0.

Проверено на маршруте, который отвечает 3 секунды: сигнал пришёл через
полсекунды после запроса.

```text
GET /slow            → {"done":true} 200 at 3.003393s     ← запрос доделан
GET /health  (после сигнала) → connection failed           ← новые не принимаются
process exited 2.5 s after SIGTERM
exit 0
```

```text
info: GET /slow 200 3002.3ms {"method":"GET","path":"/slow","status":200,"durationMs":3002.29}
```

## Срок остановки

На всю остановку отведено 10 секунд. Если запрос или служба не
закончились за это время, приложение выходит принудительно с кодом 1:

```text
[bazis] Graceful shutdown did not finish within 10000ms. Forcing exit.
exit 1
```

Клиент такого запроса получает разорванное соединение. Срок меняется в
`runApp`:

```ts
await runApp(AppModule, { kernel: { shutdownTimeoutMs: 20_000 }, http: { … } });
```

Второй сигнал во время остановки завершает процесс сразу, с кодом 130 —
так `Ctrl+C`, нажатый дважды, не ждёт.

| Ситуация | Код выхода |
| --- | --- |
| Остановка уложилась в срок | `0` |
| Срок остановки вышел | `1` |
| Второй сигнал во время остановки | `130` |
| Не запустилось: конфигурация, подключение, срок запуска | `1` |

Срок остановки должен быть меньше, чем оркестратор ждёт после `SIGTERM`
до `SIGKILL`: в Kubernetes — `terminationGracePeriodSeconds` (по
умолчанию 30 секунд), в Docker — `docker stop --time` (по умолчанию 10
секунд, поэтому для приложения со сроком 10 секунд задайте больше).

## `/health` для оркестратора

`/health` проверяет всё, без чего приложение не обслуживает запросы, —
подключения из `@Infra`, кэш, фоновые службы:

```text
база работает:       {"healthy":true,"checks":[{"name":"infra:db","healthy":true,…}]}            200
база не отвечает:    {"healthy":false,"checks":[{"name":"infra:db","healthy":false,…}]}          503 за 1.0 с
база снова работает: {"healthy":true,…}                                                          200
```

Каждая проверка подключения ограничена секундой, весь отчёт — пятью
(`http: { health: { timeoutMs } }`), поэтому зависшая база даёт `503`, а
не зависший ответ.

| Когда | Что отвечает |
| --- | --- |
| Приложение ещё запускается | Соединение отклонено: сервер слушает только после старта |
| Работает | `200` |
| Зависимость недоступна | `503` |
| Остановка началась | Соединение отклонено |

### Kubernetes

`/health` — проверка **готовности**: пока она не `200`, трафик на экземпляр
не идёт. Для проверки **жизни** берите TCP-порт: если база временно
недоступна, перезапуск приложения не поможет, а `/health` в liveness
перезапускал бы все экземпляры разом.

```yaml
containers:
  - name: shop
    image: registry.example.com/shop:1.4.2
    ports: [{ containerPort: 8080 }]
    env:
      - { name: BAZIS_ENV, value: production }
      - { name: HOST, value: "0.0.0.0" }
      - { name: PORT, value: "8080" }
    readinessProbe:
      httpGet: { path: /health, port: 8080 }
      periodSeconds: 5
      timeoutSeconds: 2
    livenessProbe:
      tcpSocket: { port: 8080 }
      periodSeconds: 10
    lifecycle:
      preStop:
        sleep: { seconds: 5 }
terminationGracePeriodSeconds: 30
```

`preStop` даёт балансировщику несколько секунд убрать экземпляр из списка
до `SIGTERM`: приложение закрывает порт сразу по сигналу, и без паузы
запросы, уже отправленные на этот экземпляр, получили бы отказ в
соединении. `sleep` в `preStop` — встроенное действие Kubernetes 1.30+, ему
не нужна оболочка в образе.

Если оркестратор опрашивает `/health` часто, а проверки дорогие, включите
кэш отчёта: `http: { health: { cacheMs: 2000 } }`.
